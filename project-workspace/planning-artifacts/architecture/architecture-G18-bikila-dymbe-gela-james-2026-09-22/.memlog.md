- (decision) [ASSUMPTION] Paradigm: Pipes-and-Filters data pipeline (backend/Supabase) feeding a read-only layered client (frontend/src). Binds: pipeline stages map 1:1 to supabase/functions/pipeline/*, frontend layers map to src/pages, src/components, src/hooks, src/lib. Prevents: pipeline logic leaking into the client or vice versa.
- (decision) [ASSUMPTION] Single npm package at repo root for the frontend; Supabase Edge Functions are separate self-contained Deno scripts under supabase/functions/, not part of the npm workspace. No monorepo tool (nx/turborepo) — team of 4, 3-month scope, boring/simple wins.
- (decision) AD: client (src/) only ever talks to Supabase via the anon key + RLS-scoped read queries through a single src/lib/supabase/client.ts; all writes (feedback, alert_rules) go through supabase/functions/ Edge Functions. Prevents a component bypassing RLS or a service-role key leaking into the frontend bundle.
- (decision) AD: pipeline steps from the brief (fetch, schema-validate, score, stage, publish-atomically, alert) each get their own file under supabase/functions/pipeline/, orchestrated by one scheduled entrypoint, so any two steps built independently can't disagree on the staging table contract.
- (decision) AD: two Supabase projects, dev and prod (brief requires separate environments). CI applies versioned migrations from supabase/migrations/ to the dev project on every PR, and to prod only after merge to main.
- (assumption) [ASSUMPTION] Frontend hosting: Cloudflare Pages (static Vite build), kept in the same provider ecosystem as the already-chosen Cloudflare Turnstile for the feedback form. Vercel is an equally valid alternative if the group prefers it -- confirm in review.
- (decision) AD: unit and property tests (Vitest, fast-check) are colocated as *.test.ts next to the source file they test; Playwright E2E specs live under tests/e2e/ since they run against a built/deployed app in a separate CI job with a different runtime. Prevents test-type conventions from drifting per contributor.
- (decision) AD: contract tests against stored MET/NVE API fixtures live under tests/contract/, fixtures under tests/contract/fixtures/. Keeps recorded third-party responses out of src/ and out of supabase/functions/.
- (decision) AD: the one-off stedskatalog build script (OSM + Kartverket -> seed data) lives in scripts/build-catalog/, run manually/on-demand, never imported by src/ or supabase/functions/ at runtime -- it only produces a migration/seed file those consume.
- (decision) AD: CI workflows under .github/workflows/ (separate from the pre-existing .github/agents/ BMAD agent configs): ci.yml (lint+typecheck+unit+property+contract tests on every PR), e2e.yml (Playwright against a preview deploy), deploy.yml (migrations + Pages deploy on merge to main).
- (direction) Deferred to later stories/updates: mobile-native app, webcam livestream feature, i18n/multi-language, catalog scaling from ~300 to ~1500 locations, real vector-field wind animation -- all already explicitly out-of-v1 in the product brief's scope table; not re-litigated here.
- (question) Open: exact push-notification delivery path (Web Push API directly vs. a provider) not pinned -- brief only says 'Web Push', no provider chosen. Left for the story that implements snøvarsel.
